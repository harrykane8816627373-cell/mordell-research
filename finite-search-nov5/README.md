## 为什么整数坐标能给严格证明

对 n 个互异整数点 p_i=(x_i,y_i)，记 N=n(n-1)/2，

```math
D=n\sum_i(x_i^2+y_i^2)-\left(\sum_i x_i\right)^2-\left(\sum_i y_i\right)^2
 =\sum_{i<j}\lVert p_i-p_j\rVert^2>0,
\qquad P=\prod_{i<j}\lVert p_i-p_j\rVert^2.
```

将它们平移到重心后，平方模和为 D/n；再乘 n/sqrt(D)，得到平方模和恰为 n 的可行构型。因此它的归一化目标值**准确等于**

```math
V(p)=\frac{n^{2N}P}{D^N}\le M_n.
```

新旧构型在同一点数的比值是

```math
\frac{V(p^{\rm new})}{V(p^{\rm old})}
=\frac{P_{\rm new}D_{\rm old}^{N}}{P_{\rm old}D_{\rm new}^{N}}.
```

程序重新计算全部点对距离、乘积和重心修正质量，再用交叉相乘判定严格增益。整数坐标即为证明输入，浮点坐标的舍入不再产生误差条款：舍入后的点集本身就是准确可行见证。坐标乘 10^10 只便于保存，不是数学归一化条件。

`verify_all.py` 还通过另一种显式重心坐标乘积核对 n≤20 的实际见证，检查点对质量恒等式、相似不变性、拒绝重复点/非整数/错误维度，并从头重建所存有理区间。接受条件使用显式异常，在 `-O` 下仍执行。

## 实际搜索范围与复算

第一波从 n=10 到 50。种子包括原保存构型、三档高斯扰动、黄金角螺旋、均匀圆盘、随机高斯，以及前一点数加外点、后一点数删内点或外点。第二波从第一波保存坐标出发，换随机种子再次执行扰动和邻点数延拓。每次优化均沿用仓库已有[自由 L-BFGS 优化器](../symmetry-breaking/explore.py)，不施加构型对称性。

两波实际共运行1455次优化、434320个迭代步骤；逐次记录没有把未运行的起点或更大点数记入范围，汇总见[搜索执行范围](search_summary.json)。

第一波的随机种子是 20261105，每次最多600步；第二波是202611052，每次最多350步。所有尝试、选中种子、实际步数、浮点梯度及停止原因保存在[第一波记录](discovery_wave1.json)和[第二波记录](discovery_wave2.json)。梯度小、线搜索停止或迭代预算耗尽分别只描述数值过程，不能作为驻点存在或稳定性的证明。

只重放最终整数认证，在仓库根目录运行：

```bash
python -B -S -O finite-search-nov5/verify_all.py
```

该入口不需要 NumPy、优化器或网络，不重写已保存报告。完整探索另外需要 NumPy；本次使用 NumPy 2.3.4，优化器来源哈希随发现记录保存。可在已安装 NumPy 的 Python 环境运行：

```bash
python -B finite-search-nov5/search.py --min-n 10 --max-n 50 --steps 600 --random-seed 20261105 --output work/nov5-search/replay-wave1.json
python -B finite-search-nov5/search.py --min-n 15 --max-n 50 --steps 350 --random-seed 202611052 --initial-discovery work/nov5-search/replay-wave1.json --output work/nov5-search/replay-wave2.json
```

浮点结果可能随软件版本和最后几位舍入略变；最终严格证书使用已保存的整数坐标和固定基线，与再次运行优化器无关。`search.py` 不覆盖原仓库的基线。

## 数学解释与下一步

增加起点确实能越过原来少量种子留下的局部能量壁垒，因此已有小梯度构型不能被视作全局最优。反过来，本专题的更高目标值也不自动证明它是局部最大。驻点存在、全 Hessian 与全局覆盖是三个独立问题，需使用各自的严格工具。

新增见证可作为[驻点存在与稳定性验证](../validated-maxima/README.md)的输入；只有该专题明确接受的点数和盒子才拥有相应严格证书。其他新见证目前只承担可达下界。一般 n 的全部最优构型、精确锐值与微观结晶结构仍未确定。
